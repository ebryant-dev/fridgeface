# Fridgeface

Five shapes. Infinite possibilities.

Fridgeface is a modular typeface built from just five shapes. Black shapes add form, white shapes cut it away. This repo is the interactive version: a board where you place, move, rotate and restack pieces to build words and pictograms.

Design and concept by [Edward Hamel](https://www.edwardbryanthamel.com). The domain glossary is in [CONTEXT.md](CONTEXT.md) and architecture decisions are in [docs/adr/](docs/adr/).

## Using it

### In a host site (git dependency)

Install a pinned tag. `npm install` builds `dist/` for you (the `prepare` script runs `vite build`; npm installs the dev dependencies it needs for that), so no prebuilt files live in git.

```sh
npm install "github:ebryant-dev/fridgeface#v1.4.1"
```

or in `package.json`: `"fridgeface": "github:ebryant-dev/fridgeface#v1.4.1"`. Then, in client-side code:

```js
import 'fridgeface'; // registers <fridge-face>
```

```html
<fridge-face share-base="https://example.com/play" style="width:100%;height:80vh"></fridge-face>
```

- The import touches `customElements` and `HTMLElement`, so run it in the browser only (in Astro: a `<script>` in the page or a client-side island, not frontmatter).
- `share-base`: the page that share links open. Default: the current URL without its hash.
- `intro`: opt in to the first-visit "play" animation (set aside since v1.2.0: without it the toy starts on a blank board). `no-intro` still switches it off.
- `no-guide`: never show the onboarding guide (and hide "Show guide" in the Controls panel). Adding it while the guide is showing ends it.
- Size: the element needs a definite size (see Embedding below). It is `display: block; width: 100%; height: 100%`, so give its parent a height or size it directly.
- Everything (styles, texture, the Jost subset) ships inside the one JS file. Nothing else to load.

### Standalone site

`npm run build:site` builds `index.html` (the toy full screen) into `site-dist/` (gitignored); `npm run preview:site` serves it. `embed.html` and the dev-only author mode are not part of it. `vercel.json` makes it deploy with no dashboard settings: import the repo in Vercel, leave everything as detected (`npm ci`, `npm run build:site`, output `site-dist`). Hashed files under `/assets/` are cached as immutable; `index.html` is always revalidated.

`index.html` carries `<meta name="robots" content="noindex">` for the staging URL. Remove that meta when a real domain is attached.

## Releasing

1. Make sure `npm test`, `npx tsc --noEmit` and `npm run build` pass.
2. Bump `version` in `package.json` (`npm version patch|minor` also commits and tags; or edit by hand), commit, merge to `main`.
3. Tag and push the tag: `git tag vX.Y.Z && git push origin vX.Y.Z`.
4. In each host, change the pin to `github:ebryant-dev/fridgeface#vX.Y.Z`, run `npm install` (updates the lockfile) and redeploy. The standalone site deploys from `main` with the repo itself.

## Sharing and export

- `getShareUrl()` returns `<share-base>#c=<encoded>`. Set the optional `share-base` attribute to the page that hosts the toy; it defaults to the current URL without its hash. Opening a link applies the composition as one undoable step, frames it, and removes the hash.
- `exportSVG()` returns a standalone SVG string; `exportPNG()` returns a 2x PNG blob (longest side capped at 4096 px). Both come from `src/export.ts`, with the same fridge texture (an embedded data-URL pattern) and magnet shadows as the board.

## Look

- **Fridge texture** (`src/texture.ts`): a seamless tile generated once per page (tileable Worley creases + value noise, embossed), used as an SVG pattern in board space so it pans and zooms with the board. The board's tone is rgb(223,222,219) (v1.4.1; v0.4.0 had lightened it to rgb(216,215,212) and v1.4.1 halves the gap to the white negative shapes, #e6e7e8, again, so they contrast less but still read); the tray uses the same tile in its original, darker tone, rgb(208,206,203).
- **Magnet shadows** (`src/shadow.ts`): no SVG or CSS filters anywhere. Each piece is drawn as [shadow, shape]; the shadow is offset copies of the geometry with round-join strokes of growing width and falling opacity. The piece being dragged, rotated or twisted lifts. Since v1.2.4 the shadow is a BOARD-space property, like a real magnet's: it is sized for the default desktop zoom (0.4 CSS px per board unit, 2.5 board units per shadow px) and grows and shrinks with the pieces as the view zooms, clamped on screen to between 0.45x (zoomed far out: still a faint contact edge, about 0.7 px at the resting offset, so white pieces read on the fridge) and 1.5x (zoomed far in: no giant blur) of that size (`shadowFactor`). The lift scales the same way. It is still one CSS variable (`--px`) set when the zoom changes, never per frame. Exports use the default-zoom proportions. v1.4.1: the shadows are 75% of what they were (offset, spread and opacity each x 0.75, resting and lifted, on the board, in exports and on the tray's shapes); the zoom scaling and clamps are unchanged.

## Suggestions (letters and words)

A **suggestion** is one way to build a letter or a word. There is never a single correct construction, so a character can have any number of numbered variants, and the panel always says so ("One way to build it. There's no right way — make your own.").

- Each suggestion is one JSON file in `src/suggestions/`. A letter is named by character and variant: `lower-a-1.json`, `upper-a-1.json`, `digit-7-1.json`, and `u0021-1.json` (code point in hex) for any other character.
- A **word composition** (a whole word, 2 to 24 characters, built as ONE composition) is `word-<slug>-<variant>.json`. In the slug, lowercase a-z and 0-9 stay as they are and every other character becomes `_x` + four lowercase hex digits (UTF-16): `play` -> `word-play-1.json`, `Play` -> `word-_x0050lay-1.json`, `hi there` -> `word-hi_x0020there-1.json`. It is reversible, and names are all lowercase, so every name is safe on case-insensitive filesystems (macOS).
- Letter format (unchanged): `{ "v": 1, "char": "a", "variant": 1, "pieces": [{ "s", "x", "y", "r" }, ...], "baseline": 0 }`. A word has `text` in place of `char`: `{ "v": 1, "text": "play", "variant": 1, "pieces": [...], "baseline": 0 }`. A file with both `char` and `text` is invalid. The letter format did not change, so v0.1.0 still reads every letter file and skips word files with a console warning. Pieces use the composition wire format. Coordinates are relative to an origin ON THE BASELINE at the letter's LEFT edge: the leftmost rotated bound is at x = 0 and y = 0 is the baseline (ascenders have negative y, descenders positive).
- The files are bundled at build time (`import.meta.glob`) and checked with the same strict rules as share links; an invalid file is skipped with a console warning. With no files, the toy looks and works as before: there is no suggestions button, no intro and no guide (the guide builds `lower-c-1`). Files light up automatically as they appear.
- **Panel:** the Letters button in the dock (or the `L` key) opens it. It has two sections. **Letters**: pick a character, then a variant thumbnail. **Words** (only when at least one word composition exists): each thumbnail shows the whole word. Either way the pieces are added on top of the board, centred in the current view, as ONE undo step, and announced. On phones the panel is a bottom sheet that closes after you place something.
- **Word layout** (`layoutWord` in `src/suggestions.ts`) puts constructions left to right on one baseline, each separated by the previous one's rotated bounds plus a gap of 60 board units (about one positive-stem width).
- **"play" intro (opt-in, set aside since v1.2.0):** only when the host adds the `intro` attribute, and on a first visit only (no auto-saved composition, no share link), the word "play" slides in from the tray in at most 1.5 seconds. If `word-play-1.json` exists, that word composition is used exactly as built (centred); otherwise, when `lower-p-1`, `lower-l-1`, `lower-a-1` and `lower-y-1` all exist, those letters are set side by side (the fallback). With neither, there is no intro. It is a normal, editable composition, not in undo history, and auto-saved. Any pointer or key input finishes it at once; with reduced motion it just appears. Without the `intro` attribute (the default) the toy starts on a blank board; `no-intro` also switches it off.

## The guide

A learn-by-doing onboarding guide, copy v3 since v1.3.0 (`src/guide.ts`, `src/outline.ts`, `src/stacking.ts` and `src/batches.ts`, pure and unit-tested; drawn by `main.ts`). The board starts blank. Each step is a small flat black-and-white callout in Jost caps with a pointer toward the real UI, and the visitor builds Edward's "c" onto **outlines** (see [CONTEXT.md](CONTEXT.md)), learning stacking on the way. **The guide never fixes the stacking order by itself:** the visitor does, prompted by the guide (only Next, the escape hatch, restacks for them). Since v1.2.3 it is the c INSIDE `word-create-1` (black oval, white oval lying on it 0.4 units left and 4 units down, wedge at 101.22 degrees about 102 units to its right), so it can stay in place as the start of "create". `findWordC` (`src/guide.ts`, pure, unit-tested on the real word) finds it without relying on indices: the leftmost positive round, the negative round overlapping it most, and the wedge nearest the round among those overlapping or within reach of the pair. The c keeps that arrangement exactly. Its place on the board is chosen for the WHOLE word: on a blank board the word's bounds are centred in the visible board (so the c sits at the word's left), and the view pans to centre the c for steps 1 to 4. Without `word-create-1` (or without a c in it) the guide builds `lower-c-1` (wedge at 111.03 degrees), centred, as before; `lower-c-1` itself is unchanged and stays a normal suggestion:

0. Only when the guide starts (on load, or from Show guide) on a board that already has pieces (an auto-saved board, a share link, a load): "Start on a clean fridge?" with **Clear and start** and **Keep my pieces** (plus Skip and Don't show again). Clear and start clears the board as ONE undoable step, then step 1 on the blank board. Keep my pieces leaves every piece untouched and puts the c's outlines (and later the word's) in EMPTY board beside the visitor's work. The spot is chosen for the WHOLE word's bounds (v1.2.3), so the word's outlines, grown from the c later, never overlap their pieces: right of the bounds of their whole composition, a margin (half a stem) clear, else below, left or above, taking the first side whose framing of their work and the outlines together keeps the smallest target (a shape's shorter side) at least 28 CSS px. The view then frames their work and the c; when that would make the targets too small (a phone, a big composition) it zooms only as far as the targets need (or until the outlines alone fill the view) and slides just enough to bring the outlines fully into view, so the outlines hug the far edge and their work stays partly in sight (they can see it is untouched while the targets stay pressable).
1. "Drag the white oval onto the fridge." Outline: the white oval (dotted). The callout points at that shape in the tray.
2. "Now drag the black oval onto it." Outline: the black oval (solid). A newly added piece lands on top, so once it clicks in it hides the white oval.
3. "Send the black oval back so the white shows through." No outline. The black oval is selected (automatically, if it is not already), so the piece action bar shows, and the callout points at its **Send backward** control (never covering it or any rotate handle). The overlap-aware Send backward steps past the white oval in one press; the step is done when the black oval is below the white one in the stacking order (bringing it forward again, or an undo, returns to step 3).
4. "Drag the wedge into place." (4a) Outline: the wedge at its angle (dotted). Dropped close but not at its angle, the callout switches to "Now turn it with the round handle to fit." (4b; on touch devices "Now turn it with the round handle to fit, or twist with two fingers.") and points at the wedge's rotate handle.
5. "That's a c." / "Want to spell "create" next?" with **Guide me** and **Clear for free play**. Without `word-create-1.json` only Clear for free play shows, and the text has no question. Clear for free play clears the board as ONE undoable step and ends the guide. If the visitor moves the finished c as one (a selection dragged or nudged; v1.2.3), its outlines follow it and the step stays "That's a c."; turned or taken apart, it is no longer the c as built and the step goes back.
6. Guide me (v1.2.3) clears NOTHING: the `word-create-1` composition appears as outlines in the same board frame as the built c (`anchorWord`), so the c's three pieces sit exactly on their outlines, count as done and their outlines never show. "Fill in the outlines to spell "create"." with a progress count that starts at "3 of 32"; filled outlines disappear; a piece close to an outline but mis-angled brings back the 4b hint. **Batches in stacking order (v1.4.0, desktop and phones):** the word is built a small BATCH at a time (`src/batches.ts`, pure, unit-tested). Wherever two of the word's pieces actually overlap (real geometry), the lower one in the word's stacking order must be placed first (`dependencies`); the c's three pieces count as placed. `planBatches` cuts the word, once, at Guide me, into batches of at most four outlines: every outline of a batch is READY (each lower piece it overlaps is already placed) and no two of a batch overlap, so they can be filled in any order; each batch starts at the ready outline nearest the last batch (a rightward step costs a little more, so the word is swept roughly left to right and nothing is left behind) and takes the ready outlines nearest it that keep the batch within a square 1.6 positive stems wide. The batches are fixed (not topped up as pieces go in): the framing holds still while a batch is filled, finishing it is a clear moment, and the current batch is simply the first one with a piece not done, read from the board, so undo and redo move between batches by themselves. Only the current batch's outlines show and accept a piece; Next fills the current batch's lowest outline. The real `word-create-1` has 18 batches after the c (batch 0): 1, 2, 1, 2, 2, 2, 3, 2, 1, 2, 1, 2, 1, 1, 2, 1, 1 and 2 outlines (its pieces are mostly one long chain of overlaps, so batches are small). **Correct by construction** (the proof is in `src/batches.ts`): a piece taken from the tray (or placed by Next) lands on top; every placed piece it overlaps is one it belongs above, because anything it belongs under depends on it and so is in a later batch, and nothing in its own batch overlaps it. So following the batches never mis-stacks anything: the unit tests place the real word in 1,000 random within-batch orders (from the c, and from nothing) and see 0 stacking prompts and 0 tangles, with every overlapping pair in the word's order. The c is the only deliberate stacking lesson. **Framing:** phones frame each batch (its outlines plus a little board around them, room above for a rotate handle) as large as the room beside the callout and the action bar allows, never closer than the c's close-up, gliding there (450 ms; instantly with reduced motion); the thinnest targets are at least 24 CSS px in portrait and 20 in landscape (the board is ~340 px tall there). Desktop keeps its comfortable zoom: the view moves only when a batch is not fully in view (sliding just enough, zooming out only if it must, never in past the comfortable zoom) (v1.4.1: the faint preview of the rest of the word that v1.4.0 drew on desktop was removed; desktop shows the current batch's outlines only, like phones). At step 7 the finished word is framed whole. Rotating the phone, or resizing between the compact and desktop layouts, keeps the batch and the progress (the plan is the same on every layout). **Stacking (v1.3.0; since v1.4.0 a safety net):** a click-in sets position and angle only; the piece stays wherever it is in the stacking order (a new piece is on top). A piece is DONE, and counts in the progress, only when it is placed AND its order is right against EVERY other placed word piece it actually overlaps (real geometry: the convex outlines the action bar's restacking uses); pairs that do not overlap never matter. Following the batches this never happens; but whenever a placed piece is stacked wrongly (the visitor restacked a piece, or dragged in one of their own that is not on top), the current batch goes back to the first one with a piece not done, and the callout's third line says "Send it back so it sits behind." or "Bring it forward so it sits in front." and points at that action-bar control, with the piece selected automatically (once per prompt, and not while the visitor is dragging, turning, or has a sheet, menu or dialog open; the turning hint takes precedence). `stackPrompt` (`src/stacking.ts`) picks the piece and the way: the most recently placed mis-stacked piece first; both directions are simulated with the real overlap-aware presses on the whole board, and the one that puts it fully right in fewer presses wins (ties: Send backward). A piece that cannot be put right by itself (its partners are themselves the wrong way round) yields to one that can, else to one a direction improves; a true tangle searches up to 5 presses of any involved piece for fewer wrong pairs and prompts the first piece of that sequence; only if that fails too is the prompt shown with no exact press count, and Next repairs the order. The word completes only when all 32 are done, so the final stacking order of every overlapping pair is Edward's. Guide me changes nothing on the board, so it adds no undo step: an undo right after it takes back the c's last action (the wedge's turn: "2 of 32", its outline shows again) and never removes the c; the guide stays on the word, and redo returns to "3 of 32". Fallback: when the c is not the word's c (the `lower-c-1` fallback) or the word anchored on it would overlap other pieces (e.g. the c was moved next to the visitor's work), the c's pieces become the visitor's own (never removed by the guide) and the word is placed fresh in empty board beside everything, starting at "0 of 32".
   (v1.2.2 to v1.3.0 filled the word letter-section by letter-section on phones and all at once on desktop; v1.4.0 replaced both with the batches above, and `src/sections.ts` was removed.)
7. "You made "create". Now try your own name." **Start fresh** (clears, one undoable step) or **Keep it**.

- **Outlines:** blueprint blue `#378ADD`, a SOLID line for a black (positive) shape and a DOTTED (dashed, round caps) one for a white (negative) shape, the same weight (about 2.75 screen px, counter-scaled with zoom so they stay crisp), a faint blue tint inside, drawn above the pieces so they read on black pieces too. One outline at a time in steps 1, 2 and 4 (none in step 3), every unfilled one of the current batch in step 6; since v1.4.1 desktop draws only the current batch too (the faint preview of the rest of the word is gone). An overlay layer that never takes pointer events. No filters.
- **Click-in (guide only):** while a step with outlines is showing, a piece of the right shape released close to an active outline (a board drag ends, a drop from the tray, a handle turn or a two-finger twist ends, or `,` `.` turning pauses) clicks EXACTLY into the outline's position and rotation, with a 170 ms settle (none with reduced motion). Close means within 18% of the shape's size (the longer side of its upright bounds), centroid to centroid, and within 12 degrees (wrapping around). **Symmetry (v1.2.4):** angles are compared modulo the shape's rotational symmetry, measured at load from each shape's real outline (`src/symmetry.ts`: turned 180, 120 and 90 degrees about its centroid, a symmetry counts when the outline lands within 1.5% of the shape's size of itself). The stems and the rounds turn onto themselves at 180 degrees (to within 0.01%; the rounds' offset axis is a tilt, still point-symmetric), the wedge at none of them. So an oval or a stem half a turn from its outline fits it, counts as filled, and clicks in at the equivalent angle NEAREST its own (it turns only the few degrees it was off, never a half turn); the 4b turning hint uses the same rule. The wedge must match its angle. The click-in is part of the same undo step as the release. Since v1.3.0 it NEVER reorders anything: the stacking is the visitor's to fix, prompted by the guide. Pieces of other shapes, or far away, stay where they were dropped. **Outside the guide nothing ever snaps.**
- **Their pieces are never touched (v1.2.1):** the pieces on the board when step 0 is answered are the visitor's, and so is anything they add or move during the guide that is not clicked into an outline. The guide tracks the pieces it built by id (clicked in, or placed by Next) and, after Keep my pieces (or once any of their pieces is back, e.g. after undoing Clear and start), Clear for free play and Start fresh remove ONLY the guide-built pieces still on an outline (Start fresh: the word, the c included), as one undoable step; Guide me removes nothing (v1.2.3). On a blank start, or after Clear and start, they clear the whole board as before. Undoing Clear and start brings every one of their pieces back in one step; if the c's outlines (nothing built yet), or the word that will grow from them, would then sit on them, they move beside them.
- **Robust:** which step shows is read from the board every time (an outline is filled when a piece of its shape sits exactly on it; the stacking is read from the board's order). Deleting or moving a clicked-in piece shows its outline again (the step goes back); undo and redo keep the guide in step with the board; nothing ever goes back past a button already chosen (after Guide me it stays on the word).
- **When:** on every visit, share links included (at once; after the intro if a host opted into it). Never in dev author mode, never with `no-guide`, never without `lower-c-1`. A share link or a load arriving under a still-untouched c starts over: step 0 when the board now has pieces.
- **Steps 0, 1, 2, 3, 4 and 6:** **Skip** (ends it for this visit) and **Don't show again** (stores `fridgeface:guide:v2` = `off` in localStorage; every access is wrapped in try/catch and a storage failure reads as not set). After about 10 seconds on a step without progress (in step 6: without a piece newly done or a new prompt) a **Next** button appears: it does the current thing for the visitor as one undoable step: restacks the prompted piece (step 3, or a stacking prompt in step 6), else fills the next outline (the piece that needs turning, else a new piece, which lands on top). **Show guide** in the Controls panel (in every section state) closes the panel and replays from the start (step 0 if the board has pieces, else step 1), even when "Don't show again" is set, without unsetting it.
- **Interaction:** only the callout itself takes pointer events. - **Accessibility:** non-modal (it never takes focus on its own; "Show guide" moves focus into it, as asked); step text, click-ins, step 6's progress and its stacking prompts go to the polite live region; its buttons are real buttons in the Tab order; `Esc` closes menus, sheets and dialogs first, then skips the guide, then deselects. ### Author workflow (for Edward, no coding needed)

Author mode exists only on the dev server and is not part of any build.

1. In a terminal in this folder: `npm run dev`.
2. Open the address it prints with `?author` on the end, e.g. `http://localhost:5173/?author`.
3. Build the letter, or the whole word as one composition (pieces may be shared between letters, overlap or cross letter boundaries), with the pieces, standing on the **baseline** (the solid line; the dashed line is the x-height guide, the height of one positive round standing upright, about two thirds of a stem). The small mark on the baseline is the origin. Stand it anywhere along the line: saving moves it so its left edge is at x = 0. The guide is the same for letters and words.
4. In the Author mode panel, type the letter or the word in **Text** (case matters: `play` and `Play` are different). One character saves a letter; 2 to 24 save a word composition. **Variant** fills in the next free number (change it to make another way to build the same letter or word).
5. Click **Save suggestion**. The file appears in `src/suggestions/` (the page reloads, and your board comes back) and the status says what was saved, e.g. `Saved lowercase s, variant 1 (lower-s-1.json).` or `Saved word "play", variant 1 (word-play-1.json).` If that file exists you are asked to **Replace** it; nothing is overwritten otherwise. Save the word `play` as variant 1 to make it the intro (shown only when a host opts in with `intro`), and the word `create` as variant 1 to offer it in step 5 of the guide.
6. To change one, click **Load** beside it in the list (it replaces the board, undoable), edit, Save and choose Replace. **Delete** removes just that file after you confirm.

The new files are ordinary source files: commit them like any other change.

## Keyboard

The board is one Tab stop; Tab and Shift+Tab always leave it. Shortcuts work while focus is anywhere inside the element (not in the share field), and `?` opens the in-app Controls list.

| Keys | Action |
| --- | --- |
| `1`-`5` | Add a piece (tray order: positive stem, positive round, negative stem, negative round, wedge) |
| `N` / `P` | Select the next / previous piece in the stacking order (one piece; wraps; pans if it is off screen) |
| `Ctrl`/`Cmd`+`A` | Select every piece |
| Arrows, `Shift`+Arrows | Move the selection 1 / 10 units. With nothing selected they pan the board |
| `Alt`+Arrows | Pan the board (`Shift` for bigger steps), even with a selection |
| `,` / `.` | Rotate the selection 1 degree anticlockwise / clockwise (free rotation, no steps; several pieces turn as one unit about their centre) |
| `]` / `[` | Bring forward / send backward, past the next piece the selection overlaps (nothing happens, and it is announced, when nothing above / below overlaps) |
| `Delete`, `Backspace` | Delete the selected pieces |
| `+` / `-`, `F` or `Shift`+`1` | Zoom, frame all pieces |
| `Space` + drag, middle-button drag | Pan with the pointer |
| `Ctrl`/`Cmd`+`Z`, `Ctrl`+`Shift`+`Z` or `Ctrl`+`Y` | Undo, redo |
| `C`, `E` | Copy the share link, open the export menu |
| `L` | Show or hide letter suggestions (only when suggestions exist) |
| `?` | Controls dialog (focus moves in, Tab stays inside, `Esc` closes and returns focus) |
| `Esc` | Closes the innermost open thing first (export menu, clear confirm, share field, letters, menu, Controls), then skips the guide if it is showing, then deselects |

### Selecting with the pointer and touch

A **selection** (see [CONTEXT.md](CONTEXT.md)) is temporary: it is not saved in history, compositions or share links. Several selected pieces move, rotate, restack and delete as ONE rigid unit, and every such action (a whole drag or rotation, or a run of 1 degree key presses) is one undo step.

- **Mouse:** click a piece to select it; drag it (or any piece of the selection) to move the selection. A drag on the empty board draws a box that selects every piece whose real shape it touches (not just its bounding box); with `Shift` it adds to the selection. `Shift`+click adds a piece or removes it. A plain click on the empty board deselects; a plain click (no drag) on one piece of a selection selects just that piece. Pan with the wheel or trackpad, `Space` + drag, or a middle-button drag.
- **Touch:** a tap selects a piece, a drag moves it (or the selection it belongs to; the drag starts once the finger has moved 8 px). One finger on the empty board pans, two pinch to zoom. Hold the empty board still for about 0.4 s (a ring appears around the finger), then drag to draw a selection box; lifting without dragging cancels it and leaves the selection as it was. Hold a piece still for about 0.4 s to add it to the selection or remove it. Two fingers, the first on the selection, twist it.
- **Overlay:** one piece shows its box and round rotate handle; several show a thin outline each, one box around them all and one handle (a 44 px target). The handle sits below the box when the spot above it is off the board or under a control. Rotating several pieces turns them about the centre of their box, fixed for the whole gesture: positions orbit and rotations add, so their arrangement is kept exactly.
- **Restacking:** bring forward moves the selection up past the next unselected piece above it that it actually overlaps (real geometry); send backward is the mirror image. The selection keeps its own stacking order and so do the other pieces. When nothing above (or below) overlaps, the button is disabled. The logic is pure and unit-tested in `src/selection.ts`.

### The Controls panel

The `?` button (the "Controls" item in the phone menu, or the `?` key) opens a panel with three sections: **Touch**, **Mouse and trackpad** and **Keyboard**. It shows only the ones the device has: Touch when `(any-pointer: coarse)` matches or `navigator.maxTouchPoints > 0`; Mouse and trackpad when `(any-pointer: fine)` matches; Keyboard when `(any-pointer: fine)` matches or a real key press (a trusted `keydown`, not an IME composition) has been seen on the page. Without `matchMedia`, or when neither pointer query matches, everything is shown. The sections follow changes live (for example an iPad gaining a keyboard or trackpad), and a "Show all controls" button reveals the hidden ones until the panel is closed. The rule is the pure function `controlSections` in `src/controls.ts`.

Screen readers: the board is `role="application"` with a name and description, and one polite live region announces changes ("Positive stem added. 3 pieces on the board.", "Moved forward. 2 of 4 in stacking order.", "3 pieces selected.", "3 pieces moved.", "3 pieces rotated to 15 degrees.", "3 pieces deleted.", "Nothing above overlaps it."). Held or repeated keys (rotate, nudge, zoom) and pointer drags are summarised once, when they pause or end. Text comes from `src/announce.ts`.

## Embedding

- Give `<fridge-face>` a definite size (a fixed or percentage height inside a sized parent); it has size containment, so it does not grow to fit its content. The compact layout (icon controls, small tray; also used for phones in landscape) follows the element's own box, not the window: a ResizeObserver on the element applies it when the element is at most 600 px wide or at most 520 px tall (not CSS container queries, which a real iPhone did not apply inside the shadow root). When the element is at most 520 px tall AND wider than tall (`layoutState` in `src/layout.ts`), the tray docks vertically along the left edge, its shapes scaled to fit the height, and the board and all its controls take the rest. The optional `--ff-bottom-reserve` custom property adds room under the tray's shapes (the standalone page puts its credit there).
- It does not need to be full viewport. `embed.html` (dev only: `npm run dev`, open `/embed.html`) shows a 900 x 600 box in a scrolling page. Wheel, pinch and touch drags that start on the board never scroll the page; the page scrolls normally everywhere else, and keys such as Space, PageDown and arrows are consumed only while the board has focus. Leave room around the element on touch devices: a swipe that starts inside it will not scroll the page.
- `share-base` sets the page that share links open (default: the current URL without its hash). The link is precomputed shortly after every change so Share can write the clipboard synchronously inside the click, which Safari requires; if it is not ready yet, or the clipboard refuses, the selectable link field appears instead.
- On notched phones add `viewport-fit=cover` to the page's viewport meta (as `index.html` does). Safe-area insets are applied only where the element actually touches a screen edge. The view stays centred on the same board point when the element resizes (window resize, rotation, the iOS URL bar).
